## 1. 执行摘要

### 问题陈述
开发者和科技从业者每天面对来自 Reddit、Hacker News、Twitter 等多个平台的海量信息，难以高效获取有价值的 AI/科技动态。现有工具存在信息过载、碎片化体验、AI 功能表面化等问题。

### 解决方案
TechPulse 是一个自主运行的 AI 科技信息收集器，通过 AI 驱动的过滤和摘要功能，从多个数据源聚合高质量的科技资讯，采用"少即是多"策略减少信息噪音。

### 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 信息信噪比 | >70% 高价值内容 | AI 评分 >6/10 的内容占比 |
| 收集延迟 | <5 分钟 | 从发布到收集的时间差 |
| 覆盖率 | >95% 热门话题 | 与人工筛选对比 |
| 每日运行成本 | <$0.50 | API 调用成本统计 |
| 系统可用性 | >99% | 自主运行成功率 |

## 2. 背景与上下文

### 为什么是现在？

1. **AI 技术爆发期** - 2024-2025 年 AI 领域发展迅速，信息量指数增长
2. **现有工具不足** - Feedly、Flipboard 等工具的 AI 功能仍然表面化
3. **API 可用性成熟** - Hacker News API 免费无限制，Reddit API 成本可控
4. **自主运行框架就绪** - 已有 autonomous-runner 基础架构

### 如果不构建会怎样？

- 继续在多个平台间切换，效率低下
- 错过重要技术趋势
- 花费大量时间在低价值内容上

### 战略对齐

与 autonomous-runner 项目目标一致：构建能够自我管理、持续运行的 AI 代理系统。

## 4. 用户故事与用例

### Epic 1: 多源信息收集

#### US-001: Hacker News 收集
```
作为一名技术开发者，
我希望自动收集 Hacker News 的热门和最新帖子，
以便我能及时了解技术社区的热点讨论。

验收标准:
Given 系统正在运行
When 到达收集时间间隔
Then 系统收集 HN Top/New/Best Stories
And 每个帖子包含标题、链接、评分、评论数
And 收集延迟 < 5 分钟
```

#### US-002: Reddit 收集
```
作为一名 AI 研究者，
我希望自动收集 AI 相关 subreddit 的热门帖子，
以便我能了解社区讨论的最新 AI 话题。

验收标准:
Given 已配置目标 subreddits (r/MachineLearning, r/artificial 等)
When 到达收集时间间隔
Then 系统通过 OAuth 收集各 subreddit 的热门帖子
And 遵守 100 QPM 的速率限制
And 包含帖子标题、链接、评分、评论数
```

#### US-003: RSS 收集
```
作为一名技术管理者，
我希望收集主流科技媒体的 RSS 更新，
以便我能追踪行业新闻和报道。

验收标准:
Given 已配置 RSS 源 (TechCrunch, Ars Technica 等)
When 有新文章发布
Then 系统收集文章标题、摘要、链接、发布时间
And 支持至少 20 个 RSS 源
```

### Epic 2: AI 驱动的信息过滤

#### US-004: 重要性评分
```
作为用户，
我希望每条信息都有 AI 评估的重要性评分，
以便我能优先阅读高价值内容。

验收标准:
Given 收集到一条新信息
When AI 分析内容
Then 输出 0-10 的重要性评分
And 评分考虑：技术影响力、讨论热度、创新性
And 评分 >7 的内容标记为"重要"
```

#### US-005: 智能去重
```
作为用户，
我希望系统自动识别重复或相似的内容，
以便我不会看到同一新闻的多个版本。

验收标准:
Given 多个数据源可能报道同一事件
When 检测到相似内容 (相似度 >80%)
Then 合并为一条记录
And 保留信息最丰富的版本
And 标注来源数量
```

#### US-006: 关键词过滤
```
作为用户，
我希望配置感兴趣的关键词进行过滤，
以便我能聚焦特定技术领域。

验收标准:
Given 用户配置了关键词列表 (如 "LLM", "GPT", "Rust")
When 收集到新内容
Then 匹配关键词的内容优先展示
And 支持正向和负向关键词
And 支持正则表达式
```

### Epic 3: 内容摘要

#### US-007: AI 摘要生成
```
作为时间有限的用户，
我希望每篇长文自动生成简短摘要，
以便我能快速了解内容要点。

验收标准:
Given 收集到一篇完整文章
When 文章长度 > 500 字
Then 生成 2-3 句话的核心摘要
And 摘要准确反映文章主旨
And 保留关键数据和观点
```

#### US-008: 每日趋势报告
```
作为用户，
我希望每天生成一份趋势分析报告，
以便我能把握当日技术动态全貌。

验收标准:
Given 一天的收集数据
When 到达每日报告时间
Then 生成包含以下内容的报告:
  - 今日 Top 10 热门话题
  - 新兴趋势识别
  - 重要公告/发布
  - 社区情绪分析
```

### Epic 4: 存储与集成

#### US-009: Markdown 文件存储
```
作为用户，
我希望收集的信息存储为 Markdown 文件，
以便我能用任何编辑器查看和搜索。

验收标准:
Given 收集到新信息
When 保存到存储
Then 使用 Markdown 格式
And 与现有 Memory 模块 (TASKS.md, CONTEXT.md) 兼容
And 支持按日期/来源/标签组织
```

#### US-010: 自主运行集成
```
作为用户，
我希望收集器能与 autonomous-runner 集成自主运行，
以便无需人工干预即可持续收集。

验收标准:
Given 配置了运行参数 (max_iterations, max_cost)
When 启动自主运行
Then 收集器作为 autonomous-runner 的任务执行
And 进度通过 progress 模块追踪
And 支持优雅停止和恢复
```

| 指标 | 目标 | 测量方式 |

- API 密钥加密存储

## 8. 技术考量

### 技术栈

- **语言**: Go 1.22+
- **框架**: 基于现有 autonomous-runner
- **AI**: Claude CLI / OpenAI API
- **存储**: Markdown 文件 (可选 SQLite)

### 数据模型

```go
type Article struct {
    ID          string    `json:"id"`
    Source      string    `json:"source"`      // "hackernews", "reddit", "rss"
    Title       string    `json:"title"`
    URL         string    `json:"url"`
    Content     string    `json:"content"`
    Summary     string    `json:"summary"`
    Score       int       `json:"score"`        // 来源评分
    Importance  float64   `json:"importance"`   // AI 评分 0-10
    Tags        []string  `json:"tags"`
    CollectedAt time.Time `json:"collected_at"`
    PublishedAt time.Time `json:"published_at"`
}
```

### API 依赖

| 服务 | 费用 | 限制 | 备注 |
|------|------|------|------|
| Hacker News | 免费 | 无 | 首选数据源 |
| Reddit | 免费(非商业) | 100 QPM | 需 OAuth |
| RSS | 免费 | 无 | 通用标准 |
| Twitter | $100+/月 | 严格 | 暂不使用 |
